## Tools built (in `pc/` and `pi/`)

- `pc/activation-watcher.py` — NMOS IS-05 take → starts/stops the GStreamer audio receiver (resolves receiver by label).
- `pc/take.py on|off` — trigger the IS-05 take.
- `pc/jitter-meter.py` — RTP inter-arrival jitter (kernel timestamps). Wired island: mean 1000us, std-dev ~600us (bursty = no ST 2110-21 shaping + WSL RX batching).
- `pc/video-web.py` — transcodes the 2110-20 flow to MJPEG and serves it at `http://localhost:8095` (Windows browser). Runs in a background task. (Originally a workaround for WSLg not showing video windows — that limitation is now fixed; see the JPEG-XS demo below.)

The Pi can't encode/decode JPEG-XS (SVT-JPEG-XS is x86/AVX2 only; the reference libjxs benchmarked ~0.6 fps at 1080p on x86).
- `pc/jxs-stream-send-file.sh <video> [--once]` — stream a real video file (instead of testsrc) through the same JPEG-XS island pipeline; auto-scales/conforms any source to 1080p59.94 and loops. The viewer auto-centers its window on screen 1 (`pc/jxs-center-window.ps1`, move-only — resizing the WSLg window freezes glimagesink). - `pc/monitor-web.py` — **IS-05 switch panel + IS-04/05 inspector** (`:8096`, iPad-friendly, **control-only**, launched by `restore.ps1`). Buttons issue real IS-05 takes to switch the active video receiver between the Pi raw ST 2110-20 (`v0`, `239.10.10.20:5005`) and the PC JPEG-XS flow (`m0`, `239.10.10.22:5008`); a third button **PC HEVC 4K** (`239.10.10.65:5010`) is not an NMOS receiver so it just disables the NMOS receivers. ## Key gotchas
- **WSLg video display now works** via `export GALLIUM_DRIVER=d3d12` (forces the D3D12 GPU instead of CPU `llvmpipe`; set system-wide in `/etc/profile.d/gpu-d3d12.sh` by `restore.ps1`). Native `glimagesink`/`autovideosink` windows render on the RTX 2080 Ti. (Previously WSLg showed no GStreamer video at all — the MJPEG browser path was the workaround.)
- **WSL renames the island NIC across reboots** — `eth1` one boot, `eth0` the next (the one holding `10.10.10.2`). NEVER hardcode the iface name; detect it by IP. All gst-based scripts now do: Python via shared `pc/island_iface.py`, bash via inline awk (`hevc-stream-env.sh`, `jxs-demo.sh`, `restore-check.sh`). ffmpeg-based `jxs-stream-*` + `jitter-meter.py` use `localaddr=10.10.10.2` (IP) so were never affected.
- **NVIDIA NVDEC/NVENC (CUDA) can't share GPU buffers with the Mesa-D3D12 GL** used by glimagesink — insert `cudadownload` (CUDA→system) first. (Zero-copy `nvh265dec ! glupload` fails `not-negotiated`.) **AND GL upload+scale of a 4K frame on Mesa-D3D12 is only ~3 fps** — do NOT `glupload`/`glcolorscale` 4K; downscale on CPU first (`cudadownload → videoconvert → videoscale → 1080p`), which sustains ~60 fps. To **fill the screen**, use **`waylandsink fullscreen=true`** (the WSLg compositor upscales the 1080p to the display on the GPU — cheap and smooth); do NOT resize a glimagesink window (freezes it) or scale 4K for display (judders, ~3 fps). The HEVC viewers use this; the centering helper (`jxs-center-window.ps1`) is now only for the JPEG-XS glimagesink viewers.
- **Streaming HEVC over MPEG-TS needs `h265parse config-interval=-1`** (re-sends VPS/SPS/PPS every IDR); without it a mid-stream joiner can't get the resolution → `unspecified size`, no video (intermittent). RTP's `rtph265pay config-interval=-1` is the equivalent.
- **WSLg can stop mapping windows after heavy gst churn** — plain `glimagesink` gets stuck at PREROLLED (never PLAYING) and no window appears though GL inits. Fix: `wsl --shutdown`, then relaunch (WSLg restarts clean).
- WSLg **audio** works even from detached/`setsid` gst, **as long as `PULSE_SERVER=unix:/mnt/wslg/PulseServer` is exported** (autoaudiosink → pulsesink, `GstPulseSinkClock`). GUI windows also work detached. In a multi-sink pipeline, if one sink (e.g. video) can't preroll, the whole pipeline stalls — so a broken video branch also kills audio.
- **In-browser video on iOS was abandoned (2026-06-09).** Re-encoding the HEVC island flow to H.264/HLS for the iPad tore on smooth motion (scrolling credits): a 1-frame seam at each HLS segment/keyframe boundary. We verified the encode was clean (uniform 29.97 cadence, closed 1×I+29×P GOPs, no B-frames, healthy frame sizes) and the **native PC viewer is pixel-perfect** — so it's an inherent iOS-HLS segment-join limit on smooth motion, not a bug. Tuning that didn't fix it (and was all removed with the preview): bitrate 6→12 Mbit, 60→29.97 fps + gop, `bframes=0 strict-gop=true aud=true`, 4 s segments. **Lesson: for smooth-motion monitoring use the native window; use `:8096` as the iPad control surface.**
- **GStreamer multi-branch pipelines need `queue`s** — splitting a `tsdemux` into video+audio branches with no `queue` runs them in one thread → `pipeline construction is invalid, please add queues` and **silent/stuttering audio**. Always `demux. ! queue ! …` per branch; for smooth audio over WSLg's **RDPSink** add deep queues + `pulsesink buffer-time=500ms`. And **GStreamer has no JPEG-XS decoder** (ffmpeg-only), so JPEG-XS can't feed a `compositor` — the multiview/output carry **HEVC** on the 5008 "Home videos" slot instead.
- **Multiview can't afford 4K** — there is **no CUDA scaler** in this gst build (`cudascale`/`cudaconvertscale` absent), so a 4K tile must `nvh265dec → cudadownload (full 4K) → CPU videoscale → 540`, which pegs NVENC/CPU and **starves the other tiles + audio (stutter)**. Run **all** multiview sources at **720p** (bbb via `media-send.sh --hevc`, not the 4K `hevc-stream-send-file.sh`). Switching bbb 4K→720p dropped NVENC 69%→10%.
- **iPad panel perf (`monitor-web.py` JS)** — never rebuild DOM via `innerHTML` inside the `requestAnimationFrame` timecode loop: doing it ~60×/s reflows the page and **freezes scrolling + the timecode itself**. Per-frame, touch only the timecode `textContent`; update the PTP info line (`innerHTML`) from `sync()` (~3 s). And **clamp the `/time` clock-offset correction to ≤40 ms/sync** (lock once, then nudge) — otherwise a laggy `/time` (PC busy) makes the displayed frames jump ~30 at a time.
- **Verify single-instance after every restart** — duplicate **senders** to one multicast group interleave packets → corrupt stream → stutter; duplicate **audio followers** play the same feed out-of-phase → sounds like stutter. Restarts here repeatedly left orphans. Caveat: `ps … | grep` / `pgrep -f` can match **your own shell** (the pattern/path is in its cmdline) and inflate counts — trust the **compositor / audio-follower counts** (one each = one renderer) and use bracket patterns. And a `pkill -f '[x]…'` still self-kills if the **bare** name appears later in the same command (e.g. an `echo "pulsesink:"` label, or a `setsid bash media-send.sh …` launch on the same line) — keep kills in their own call with no bare literals. The "Music audio stalling like crazy" turned out to be exactly this: a **stray Pi-raw audio follower** left over from source-switching, fighting the Music follower at the sink. One `pulsesink` = correct.
- **Legacy `decodebin` can't autoplug some H.264 on GStreamer 1.28** — it reports `Missing decoder: H.264 (High Profile)` for `bbb-4k.mp4`'s 4K/High-profile/avc stream even though `nvh264dec`/`avdec_h264` are present with good rank and explicit `h264parse ! nvh264dec` decodes fine. **Use `decodebin3`** in the senders (`media-send.sh`) — it autoplugs correctly and auto-selects one stream per type, so multi-audio files (bbb-4k = mp3+ac3) don't leave an unlinked pad that EOS-loops the pipeline. And **never `rm ~/.cache/gstreamer-1.0/registry.*` then run a *single-element* `gst-inspect`** — that leaves an incomplete registry (decodebin autoplug breaks for new processes); rebuild with a full bare `gst-inspect-1.0`.
- **Run senders/renderer from a Linux copy (`~/atoll-run`), not `/mnt/c`** — the 9p cache can hand a stale/half-written script to fast (background) reads, so `setsid bash /mnt/c/.../media-send.sh` ran an OLD version while a foreground run of the same path worked. `launch-media.sh` copies `pc/*.sh` → `~/atoll-run` and runs from there; logs go to `~/atoll-run/logs` (user-owned — old root-launched senders leave root-owned `/tmp/*.log` that block the user's `>`).
- **A remote tile feed must arrive at ≥ realtime** — a source delivered *slower* than realtime (the Mac's pacer once gave **0.70×** due to a drift-accumulating sleep loop under launchd background QoS) starves the bridge + renderer so **video and audio in that tile hitch together**; no PC-side buffer fixes steady under-delivery. Diagnose by capturing the source `.ts` and comparing its video PTS span to wall-clock.
- **A short / odd-timestamp file can make a file-paced `udpsink` emit nothing.** The Test Reels clips are short, **vertical 1080×1920** phone reels; as a folder playlist the encoder restarted every ~9 s AND the clips' odd PTS made `udpsink sync=true` transmit nothing (5014 empty → the tile/single pipeline never prerolled → selecting it killed the output, no video). Fix: `build-reels-loop.ps1` concatenates them into ONE continuous 720p file with **timestamps reset** (`setpts=PTS-STARTPTS`), pillarboxed; the sender then feeds a stable stream like the long-file channels. **Diagnose transmit first** (`tcpdump … dst port <p>`) before blaming decode — the encode+mux to a `fakesink` was fine; only the `udpsink` was silent.
- **Assignable multiview: every assigned slot source must feed *continuously*.** The compositor stalls on any tile whose pad never gets caps (a dead OR briefly-gapped feed at preroll) — `ignore-inactive-pads` doesn't rescue a never-fed pad. So a flaky/short-clip source dropped into a slot can stall the whole 2×2. Keep all channels as continuous streams (long files / loops).
- **The virtnode's v0/m0 IS-05 "takes" are decorative.** `m0`'s active connection is `master_enable:false`, `sender_id:null` — not actually connected; the panel takes just toggle `master_enable` on auto-generated example receivers, and `output-render.sh` does the real rendering (direct multicast join). There are **no spare video/mux receivers**, and HEVC-over-MPEG-TS isn't a standard NMOS RTP transport. To make a channel genuinely *discoverable*, register a real source→flow→sender with the Registration API (`reels-nmos.py`, heartbeated under the registry's 12 s expiry) + serve an SDP — that's a stronger showcase than the existing channels.
- **Launch the panel as the USER, not root.** `restore.ps1` once launched `monitor-web.py` via `Start-Process wsl -u root` and it died right after start (8096 came up empty); the persistent hidden window **as the user** holds it fine.
- nmos-cpp virtnode **regenerates resource UUIDs** — always resolve receivers by **label**.
- IS-05 receiver has **2 transport-param legs** — PATCH only `master_enable`+activation, not a 1-elem `transport_params`.
- Static IP/firewall need **elevated** PowerShell. Firewall rule "ST2110 media inbound (WSL)" opens UDP 5004,5005,319,320. Docker uses host ports 8080/8081/8090/8091/1883.
- Run a **single** `ptp4l` (extras pile up; `sudo pkill ptp4l` then start one).
